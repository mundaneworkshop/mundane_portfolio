# sig fig Blender pipeline

Turns a Studio `.io` into a rigged, decimated, animated GLB for the hologram (see `docs/project-history/sigfig-lab.md`).
Two scripts run INSIDE Blender (tested on 5.1; the Blender MCP's `execute_blender_code` is the usual way to run them).

| file | what it does |
|---|---|
| `ldr_to_blender.py` | `.io` -> rig in a collection `sigfig-<id>`; decimation pass; `export_glb()` |
| `idle_anim.py` | a JSON motion spec -> keyframes on the rig, exported as the glTF animation `idle` |
| `choreo.py` | a keyed story plan (`plans/*.json`: timed poses, shakes, pivots, a prop that flies, arms aimed at targets) -> the same `idle` clip, for long narrative loops |

```python
exec(open('/path/to/repo/tools/sigfig-blender/ldr_to_blender.py').read())
exec(open('/path/to/repo/tools/sigfig-blender/idle_anim.py').read())
info = build_sigfig('/path/mw-sigfig-vr-gamer.io', 'vr-gamer')            # tri_budget=9000, safe=True, roles=None
apply_idle('vr-gamer', SPEC)                                              # see idle_anim.py for the spec format
export_glb('vr-gamer', '/path/mw-sigfig-vr-gamer-idle-v1.glb')
restore_scene()                                                           # puts the scene's fps / frame range back
```

## What the importer does
- Reads `model2.ldr` from the `.io` (a flattened LDraw: part geometry is inlined, no LDraw library needed). Colours are Studio colour codes, read at run time from `/Applications/Studio 2.0/data/StudioColorDefinition.txt` (nothing from BrickLink's table is stored in the repo); LDraw direct colours (`0x2RRGGBB`) work too. Falls back to a small palette if Studio is not installed.
- One mesh per part, **origin at the part's joint** (shoulder, hip, neck, wrist), named by role: `head torso hips arm_l arm_r hand_l hand_r leg_l leg_r`, plus `acc_<part>` (near the head, a hand, the torso or hips) and `prop_<part>` (free: a bike, skis). The figure's right is -X in LDraw; roles follow the figure's own left/right.
- Hierarchy: hips > legs, torso > head, arms > hands > held props; accessories under what they sit on. Feet at z = 0, facing -Y (glTF +Z).
- Blender object names are `<fig>:<role>` so several figures share a scene; `export_glb` renames them to the bare roles for the export only.
- Primitives Studio does not embed (`48/4-4cyli.dat` cylinder walls, `…disc.dat` caps, `…edge.dat` outlines) are generated by `_synth()`; any other unresolved reference is listed in `info['unresolved_refs']` rather than dropped silently. Without this the figure loses about a quarter of its geometry (round sleeves, the neck, the hand clip's interior, headset tubes).
- Custom Studio parts (the slate dummy's `m64a4bc45_*`) carry no usable part number. Pass `roles={'m64a4bc45_202587_011646': 'head', ...}`.
- **Prints are imported.** Studio embeds a part's print in `model2.ldr` as a `PE_TEX_INFO` base64 PNG on the part's `FILE` section, and the texture shell's triangles carry one (u, v) per corner. The importer reads both, composites the print over the part colour (glTF cannot mix a colour with a texture) and exports it as a base colour texture with a UV map (the usual printed face). Studio's v runs bottom-up like Blender's. Multi-colour printed parts (torso, hips, controller) are plain coloured geometry and need nothing.
- **Print audit.** `build_sigfig()` returns `info['prints']` (per part: textures and colour count) and `info['print_warnings']`: a part whose number looks printed (`pb####`, `tex`, `bl_`) that came in as a single plain colour, a texture no face uses, or any image file in the .io that was not imported. Read it after every import; the rule is that whatever the .io carries must reach the GLB.

## Decimation (why it is gentle)
`build_sigfig(..., tri_budget=9000, safe=True)`:
1. Merge coincident points (the importer makes three per triangle). It deliberately does not dissolve coplanar faces: re-triangulating the merged n-gons bridged the concave notch of the C-shaped hand clip.
2. `safe=True`: body parts and any multi-colour printed part (3+ materials) are left at full detail; accessories and props (hair, helmets, headsets, bikes) are collapse-decimated, never below 70%. A vertex group pins every vertex on an open edge or a colour border at weight 0, so outlines and print edges do not move (checked: open-edge counts identical before and after). A plain collapse moves them, which tore holes in the neck bracket and chewed the controller's button prints.
3. `tri_budget` is a target, not a ceiling: protected parts are never thinned, so a figure can land above it. `safe=False` also thins body parts (measurably rougher on round limbs).
Pilot (VR gamer): 16,887 triangles complete -> 15,487; props lose more (the biker's bike halves to ~70%).

## The request queue (how the Sig Fig Lab uses this)
The Lab's "Idle loop" box queues a request in the artifact db (`requests/<fig id>`, status `queued`) with the `.io` stored as an asset. Nothing runs by itself; the user asks Claude to "run the sig fig queue". The runner:
1. `ArtifactData query` collection `requests` where `status == queued`; set the doc to `working`.
2. `Artifact read` with `path` = the request's `ioAsset` id to download the base64 text, decode it to a `.io` file.
3. In Blender: `build_sigfig(...)`, write a `SPEC` from the description, `apply_idle`, `export_glb`, `restore_scene()`, delete the figure's collection and its orphaned meshes / materials / actions (leave the user's Cube, Camera and Light alone).
4. Base64 the GLB to a `.txt`, upload it with `Artifact publish asset:true` (the asset store takes no `.glb`), then `ArtifactData update` `sigfigs/<id>` `glbs` with `{uid, name, size, at, asset}` and `requests/<id>` to `done` with a note and the spec (or `failed` with the reason).
Each run adds a new GLB (`-idle-v<N>`); remove the old one from the card and its asset.

## Story choreography (`choreo.py`)
For idles that are a sequence rather than a sine wobble. `apply_plan(fig_id, plan)` keys every part per frame from a plan JSON (`plans/vr-gamer-rage-quit.json`, generated by `plans/make_vr_gamer_plan.py`): periodic Catmull-Rom keys per part/channel, windowed shakes, a free prop keyed in world space (re-parented to the root), and arms aimed at named targets (grips, a fist hovering over / hitting the print, the face, the back pocket) with per-frame weights. Always call `build_sigfig` fresh before `apply_plan` (it slices meshes and re-parents objects).
- **Torso and head are skinned**, not rotated as rigid blocks. A short bone chain (`torso_0..4`, `head_0..3`) runs up the bottom of each mesh; the mesh is sliced there and weighted along the chain. `rotation_x` = bend forward, `rotation_y` = bend sideways, `rotation_z` = twist, spread along the chain, so the bottom of the torso stays flush on the hips and the bottom of the head on the torso while the geometry between stretches. Arms, headset and hair are parented to the bone at their height. The GLB therefore has a skin: the site's hologram shader must support skinning and any clone must use `SkeletonUtils.clone`.
- Prop orientation: `base: "print_up_handles_in"` puts the controller's printed face up with its two side handles pointing at the figure (local +z up, local -y toward the body; the figure's left hand grips local -x).
- **Grips** (`hand_grips` in the plan): while a hand's grip weight is up, `choreo.py` solves the arm and the hand so the C clip ring (axis = the hand's local y, opening = local -z, ring centre (0,-0.114,0.04); constants in `HAND_RING`) lands on the handle point (first priority), with its axis along the handle and its opening away from the print as far as the joint allows. The hand turns about the pin where it slots into the arm (`HAND_PIVOT`, hand-local (0,-0.04,-0.005), where the pin leaves the arm), NOT about the hand's origin, which sits 4 cm inside the arm: rotating about the origin swings the pin's exit point off the arm. Hand-vs-controller overlap is tolerated; placement comes first. A prop can be keyed *about the gripping hand* (see `held()` in `plans/make_vr_gamer_plan.py`).
- `clipcheck.py`: `clipcheck()` counts overlapping polygons between named parts at given times, `gaps()` gives the closest distance. Use it to keep overlap with the headset down; zero is not required.
- Reach: the aimed hand only reaches about 0.2 m from the shoulder; place props and strike points within that (lean the torso in to help).
Feedback in the Lab: the card shows queued / working (step n of 6, elapsed, progress bar) / done, and a toast when a GLB lands. Requests only start when the user tells Claude "run the sig fig queue".
