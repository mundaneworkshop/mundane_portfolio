Sig fig lab

Intake for the minifigure sig figs. Drop each sig fig's Studio file and its Blender GLB, check the GLB against the part and idle-loop conventions, watch the idle loop, write the About copy that shows in the manual, set how it unlocks, then export a bundle for the repo.

How a sig fig gets from Studio to the site

Pipeline

  1. Build the sig fig in Studio, export mw-sigfig-<id>.io.
  2. Export it from Studio as .dae or .obj with textures, bring it into Blender, name the parts below.
  3. Keyframe a 2 to 4 second loop named idle on the parts.
  4. Export a binary .glb without Draco compression (this page cannot preview Draco).
  5. Drop the .io and the .glb here. Files named mw-sigfig-<id>… land on the right card by themselves.
  6. No Blender work needed: describe the idle on the card, press Request, and ask Claude to run the queue. It builds the rig and idle from the .io and adds the GLB to the card.
  7. Write the copy, set the unlock, then Export bundle.

Part names the checker looks for

  • head, torso, hips
  • arm_l, arm_r, leg_l, leg_r
  • Props keep their own names (bike, board, helmet).
  • Do not join meshes: the idle moves each part.
  • Feet at the origin, facing +Z, one scale for every sig fig.

What the bundle holds

  • assets/outfits.json: names, order, copy, unlock rules, idle clip, parts.
  • assets/models/outfits/<id>/…glb for every GLB.
  • Unzip at the repo root, commit, push.
  • Models, thumbnails, copy, unlock rules and order are all stored with this page, so any browser sees the same sig figs.
