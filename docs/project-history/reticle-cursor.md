# Targeting reticle cursor (Oct 7 2026)

One cursor for the whole site and for the Framer case-study pages: amber corner brackets that ride the pointer with the Delight Lab "float" easing, and lock onto media.

**Single source:** `assets/bric-reticle.js` (plain JS, no imports, one function, `bricReticle(opts)`). `index.html` loads it with a script tag and starts it with `scope: 'page'`. Framer gets the same file pasted verbatim into a code component (`ReticleCursor.tsx`, generated by `framer-code/sync-reticle.js` in the bric-ds folder), so edit the behaviour here and nowhere else.

**Motion (from `case-study-explorations/02-delight-lab.html`, tray 5):** 44px bracket box at the pointer, 12px arms, 2px, `register/amber/solid`. Every move eases with 250ms `cubic-bezier(.34,1.56,.64,1)`. Over a `[data-bric-media]` element the box expands to the frame (6px outside it) and shows `▸ OPEN · n OF N` (n counted among elements sharing `data-bric-group`, default group order). It leaves by contracting to the pointer while fading. The corners move with `transform` only (four 12px elements), not width/height/left/top.

**Where it shows (page scope):** everywhere there is a desktop mouse. It steps aside and the native cursor returns over anything that authors its own cursor: links, buttons, inputs, `contenteditable`, `cursor:grab` handles, and the galaxy canvas while a planet is hovered (the canvas sets an inline `cursor:pointer`). `auto`, `default`, `crosshair` and `none` are treated as "no cursor of its own", so the plain canvas and the planet-view crosshair show the reticle. The module reads the page's authored cursor by briefly lifting its own hiding rule, cached per element + class + inline cursor + body class. If a future component switches its cursor some other way (a stylesheet rule on a parent, say), add it to `ignore` or `plainCursors`.

**Per-target geometry (v1.3):** an element can set `--bric-ret-arm`, `--bric-ret-weight`, `--bric-ret-outset` (negative = inside the element) and `--bric-ret-glow:1` as CSS custom properties; a virtual target can return `arm/weight/outset/glow`. The corner pieces are drawn at 32px/4px and scaled, so arm and weight animate with transform only. Framer uses this for the hero (brackets land on its corner marks, 32px, 4px, glow) and the rail's chapter plates.

**Not touched:** touch and pen input (pointerType must be `mouse`), keyboard focus (focus rings stay), click handling (the page opens its own lightbox). `prefers-reduced-motion` removes the easing; the reticle still shows.

**What it frames on this site (v1.2):** planets, the entry-gate monogram and pinned messages are treated as media.
- *Labels are the verb only* (`▸ OPEN`, `▸ READ`, `▸ ENTER`), no `n OF N` on the galaxy objects. Media (`data-bric-media`) keeps `n OF N`.
- *Kit box and artifact moons (focus view):* the kit-box face that already highlights on hover (`boxHoverFace`, only when the case study CTA is active) is framed using the face plane's bounds, label from the site's own `#box-hover-label` text (e.g. `▸ VIEW CASE STUDY`). The legacy hover visuals (the dark face-dim plane and the centred DOM label) are switched off whenever `<html data-bric-reticle>` is set; face detection, the click handler and the `body.box-hovered` pointer fallback are unchanged, so without the reticle the old hover still works. Artifact moons are raycast by the resolver itself (the site had no moon hover), label `▸ OPEN`; an uploaded model is framed instead of the larger placeholder mesh. The focused moon is not re-framed.
- *Planets:* a virtual target. The resolver (`targets` option, registered near `setHovered` in `index.html`, exposed as `window.__bricReticleTargets`) answers "when" from the canvas's own inline `cursor:pointer` (set by `setHovered` and the entry-gate handler) and "where" from the planet's `hitProxy` bounds projected to the screen. `rect()` is read every frame, so the brackets follow the planet as the galaxy turns and it scales up on hover. Label `▸ OPEN · n OF N` among visible planets.
- *Monogram (entry gate):* same resolver, frames `mwQuad`, label `▸ ENTER`. The frame is the billboard quad's bounds, a little looser than the mark itself.
- *Pinned messages:* plain DOM. `makeBeacon` adds `data-bric-target`, `data-bric-group="msg"`, `data-bric-label="▸ READ · {n} OF {N}"` and `data-bric-label-at="below"` (the label sits under the frame so it does not collide with the "incoming transmission" hover text).
- Anything else can opt in with `data-bric-target` (or `data-bric-media` for a lightbox image). Chapter-ring labels (`.cschlbl`) and the like still use the native pointer; add the attribute if they should be framed too.

**Testing:** `window.__bricReticle` is the live instance; `<html data-bric-ret="hot">` is set while the native cursor is hidden; `<html data-bric-reticle>` is set while the module runs.
