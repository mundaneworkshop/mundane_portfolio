# Targeting reticle cursor (Oct 7 2026)

One cursor for the whole site and for the Framer case-study pages: amber corner brackets that ride the pointer with the Delight Lab "float" easing, and lock onto media.

**Single source:** `assets/bric-reticle.js` (plain JS, no imports, one function, `bricReticle(opts)`). `index.html` loads it with a script tag and starts it with `scope: 'page'`. Framer gets the same file pasted verbatim into a code component (`ReticleCursor.tsx`, generated by `framer-code/sync-reticle.js` in the bric-ds folder), so edit the behaviour here and nowhere else.

**Motion (from `case-study-explorations/02-delight-lab.html`, tray 5):** 44px bracket box at the pointer, 12px arms, 2px, `register/amber/solid`. Every move eases with 250ms `cubic-bezier(.34,1.56,.64,1)`. Over a `[data-bric-media]` element the box expands to the frame (6px outside it) and shows `▸ OPEN · n OF N` (n counted among elements sharing `data-bric-group`, default group order). It leaves by contracting to the pointer while fading. The corners move with `transform` only (four 12px elements), not width/height/left/top.

**Where it shows (page scope):** everywhere there is a desktop mouse. It steps aside and the native cursor returns over anything that authors its own cursor: links, buttons, inputs, `contenteditable`, `cursor:grab` handles, and the galaxy canvas while a planet is hovered (the canvas sets an inline `cursor:pointer`). `auto`, `default`, `crosshair` and `none` are treated as "no cursor of its own", so the plain canvas and the planet-view crosshair show the reticle. The module reads the page's authored cursor by briefly lifting its own hiding rule, cached per element + class + inline cursor + body class. If a future component switches its cursor some other way (a stylesheet rule on a parent, say), add it to `ignore` or `plainCursors`.

**Not touched:** touch and pen input (pointerType must be `mouse`), keyboard focus (focus rings stay), click handling (the page opens its own lightbox). `prefers-reduced-motion` removes the easing; the reticle still shows.

**Not done yet:** the site has no `[data-bric-media]` elements, so the lock-on-media behaviour and the n OF N label are dormant here; tag images (and their lightbox) when that exists.

**Testing:** `window.__bricReticle` is the live instance; `<html data-bric-ret="hot">` is set while the native cursor is hidden; `<html data-bric-reticle>` is set while the module runs.
