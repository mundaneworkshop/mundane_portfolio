# Sig Fig Lab (intake artifact for the minifigure sig figs)

> Published artifact: https://claude.ai/artifact/V3az3EFrjqm1g6hSeD3GiA. Source of truth: `tools/sigfig-lab.html` (republish that file to the same URL to update it; capabilities `db` + `downloads` + `assets`). Modelled on the Arcade Fleet Lab (`arcade-ships.md`). Added Oct 23 2026.

A "sig fig" is one outfit of the hologram minifigure (see `outfits.md`). The Lab is where the first batch (`mw-sigfig-*.io` in `Render staging/mw sig fig`) is taken from Studio file to something `assets/outfits.json` can load.

**Per sig fig the Lab holds:** name, order (carousel order; the first visible one is the free default), show/hide, the Studio `.io` (only its thumbnail and part list are read; the file is not exported), one or more GLBs, a GLB check, the About copy (kicker / title / body / locked teaser), an unlock rule, and idle-loop notes. Ten sig figs are seeded in the page (`SEED`: work, slate-dummy, vr-gamer, rebel-pilot, tie-pilot, og-boba, iron-man, biker, skier, chef) with suggested unlock rules (case study for the two project ones, arcade goals for the Star Wars ones, minikit tiers for the rest) that are meant to be edited.

**Intake.** Drop `.io` / `.glb` files on the top zone: `mw-sigfig-<id>[-v2…].io|glb` goes to the matching card, anything else is listed as not placed (drop it on a card instead). `.io` files are read in the browser (zip + `DecompressionStream`): the Studio thumbnail becomes the card image and `model.ldr` gives the part count and which minifig parts exist.

**GLB check** (per card, across all its GLBs): looks for the seven body parts by node name (`head`, `torso`, `hips`, `arm_l`, `arm_r`, `leg_l`, `leg_r`; loose variants like `Left_Arm` match), an animation clip named like `idle` (with its duration), triangle and texture counts, and size (warns over 3 MB). The Parts and Idle step chips go green only when these pass. **Draco-compressed GLBs cannot be previewed** (the artifact CSP blocks the decoder), so export from Blender uncompressed; the site itself can still load Draco.

**Live preview.** One sticky stage (three r128): pick a card's Preview, choose a clip, pause, speed 0.25–2×, turntable, drag to rotate. The figure is scaled to a common height, like the site's outfit loader.

**Unlock rules** use the arcade's vocabulary (`arcade-ships.md`): `free`, `minikits`, `destroy` (+target), `hunters`, `planets`, `survive`, `plays`, `rank`, `score`, plus `caseStudy` (target = `w0` Meta Horizon Worlds, `w1` Slate Auto, `w2` Josh.ai, `cv`). The Lab previews the locked message the site should show ("Shoot 15 minikits in the Space Arcade to unlock", "View the Slate Auto case study to unlock").

**Export bundle** (zip, unzip at the repo root): `assets/outfits.json` + `assets/models/outfits/<id>/<file>.glb`. Entry shape: `{id, name, enabled, unlock:{type,n?,target?}, unlockAt, about:{kicker?,title?,body?,teaser?}, idle:<clip name>|null, parts:[{file}]}`. `unlockAt` is the minikit count for `minikits` rules and 0 otherwise.
- **The site reads today:** `id`, `name`, `enabled`, `unlockAt`, `about`, `parts`. `unlock` and `idle` are ignored.
- **Not built yet on the site (follow-ups):** (1) play the `idle` clip (the loader only takes `gltf.scene`; needs an `AnimationMixer`, held on the first frame under reduced motion); (2) the unlock engine for every rule type other than `free` and `minikits`, including recording which case studies a visitor has opened. Until (2) lands, a sig fig with another rule type exports as unlocked. The Lab flags those cards.
- The bundle replaces `assets/outfits.json` wholesale and includes every sig fig that has a GLB (fetched from storage, so any browser works); sig figs with no model yet are listed as left out. Keep the GLBs in the Lab after committing them, or the next export will drop those sig figs.

**Storage (all hosted with the artifact, nothing local).** Names, order, copy, unlock rules, notes and file lists sync through the artifact db (collection `sigfigs`, one doc per sig fig, only fields changed from the seed). GLBs and the Studio thumbnails are stored in the artifact's asset store (`assets` capability), with the asset ids kept on the db docs, so any browser or device sees the same sig figs and Export bundle works from any of them. The asset store takes no `.glb` type, so each GLB is stored as base64 text (`text/plain`) and decoded on read (`getBlob`); that caps a model near 15 MB (20 MiB store limit, +33% base64), and the Lab refuses larger files with a message. The page shows a storage meter (`assets.list()` usage). The `.io` itself is also stored (base64 text, like a GLB) so Claude can build from it; the card keeps its thumbnail (PNG asset) and part list. Removing a GLB or `.io` deletes its asset. Only people who can edit the artifact get the `assets` capability; in a view without it the Lab falls back to a browser-only IndexedDB cache and says so in the banner. The IndexedDB cache is also kept alongside the assets as a fast local copy.

## Idle requests: describe it, Claude builds it in Blender (Oct 23 2026)

Each card has an **Idle loop** box: describe the motion (or what to change on the next pass), optionally set a triangle target, press **Request idle from Claude**. That writes `requests/<fig id>` (`status: queued`, the description, `ioAsset`, `triBudget`) and the card shows its status (queued, working, done with a note, failed). The page cannot wake Claude, so the user then asks Claude to **run the sig fig queue**; the runner (procedure in `tools/sigfig-blender/README.md`) pulls the `.io` out of the artifact's storage, builds the rig and idle in Blender through the Blender MCP, exports a GLB, uploads it as an asset, attaches it to the card's `glbs` and marks the request done. The card then previews it like any GLB; each run adds a new `-idle-v<N>` file.

**Scripts** (`tools/sigfig-blender/`, run inside Blender): `ldr_to_blender.py` (`.io` -> named, jointed, parented rig + decimation + GLB export) and `idle_anim.py` (a JSON motion spec of sine layers -> a seamless 4 s `idle` clip). Read the README for the role names, the spec format and the decimation rules.

**Missing-geometry lesson (do not undo):** the 'missing planes' on the VR gamer's neck, hands, arms and headset were NOT decimation. Studio's `model2.ldr` references LDraw base primitives it does not embed (high-res cylinder walls `48/4-4cyli.dat`, caps `…disc.dat`, outlines `…edge.dat`), and the importer used to drop any reference it could not find, silently deleting about 28% of the figure (VR gamer: 12,087 -> 16,855 triangles once restored). `_synth()` in `ldr_to_blender.py` now generates `cyli` / `disc` / `edge` (any fraction, any of the 48/, 8/ or standard resolutions), and `build_sigfig` reports any still-unresolved reference in `info['unresolved_refs']` (all ten figures: none). Check that list whenever a figure looks thin.

**Decimation (separate, and gentle by design):** a first pass that collapsed everything toward 9k also roughened the arms and moved open edges and colour borders on LEGO's open shells, and an earlier dissolve-coplanar step bridged the hand clip's concave notch. The shipped pass merges coincident points only, leaves body parts and printed (3+ colour) parts at full detail, and thins only hair / helmets / props, never below 70%, with a vertex group pinning every open edge and colour border so outlines do not move. `triBudget` is a target, not a ceiling. Pilot: VR gamer 16,887 -> 15,487 triangles; `safe=False` also thins body parts.

**State of the pilot:** the VR gamer's `.io` is stored, request `vr-gamer` is done, and its card holds `mw-sigfig-vr-gamer-idle-v3.glb` (idle 4.00 s, all seven parts found, 15,487 triangles). All ten `.io` files import without errors; eight of ten resolve every body role. Not yet resolved: the skier (a single custom leg part) and the slate dummy (custom `m64a4bc45_*` parts), both need `roles={...}` overrides in `build_sigfig`. The printed face IS in the `.io` (an embedded PNG plus per-face UVs on the head's texture shell); an earlier version of this note and the importer wrongly said otherwise and shipped plain heads. The importer now reads it and audits every import for prints (`info['print_warnings']`).
