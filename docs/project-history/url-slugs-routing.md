# URL slugs + client-side routing

> Editable URL slugs + client-side routing added to index.html (projects, moons, CV, HoloNet) — read before touching routing, deep-links, or the manual booklet's title area. Built Aug 13 2026.

Built Aug 13: editable, shareable/deep-linkable URLs for the galaxy site. Scope, confirmed with user: projects (planets) get `/work/<slug>`, each project's moons get `/work/<project-slug>/<moon-slug>` (nested, editable in the booklet under the title, same click-to-edit pattern as tags/links), CV gets one slug `/cv` (route nodes stay in-page, NOT individually addressable — user explicitly declined per-node slugs), HoloNet gets one slug `/holonet` (internal dev id is `contact`, not a separate page — user caught this, "Contact" was leftover code-comment naming). User is not on Vercel Pro, so per-project analytics via custom events was explicitly ruled out — slugs are for shareability/deep-linking only, not analytics breakdown.

Where slugs live: project slug in `CASES[id].slug`, restored from `copyOvr['case:'+id+':slug']` at boot — **must be in the field-restore whitelist array** (search `'kicker','title','body'...` list) or edits silently don't survive reload (hit this bug, fixed). Moon slug lives directly on the moon's meta object (`copyOvr['artmeta:'+editId]`), persists fine without a separate restore step since `getMoonMeta` always reads live. CV/HoloNet slugs are simple vars (`cvSlug`/`holonetSlug`) seeded from `_bootCopy`, edited via new fields in the existing `#dbg-cv`/`#dbg-holonet` Edit Mode panels (not the booklet — those two views don't use the booklet at their top level).

Routing helpers added near `CASES` definition (~line 9426): `slugify()`, `uniqueSlug()` (collision-safe, appends -2/-3), `setRoute()` (pushState guard). `setRoute` calls added at the end of `openCase`/`openCV`/`openContact`/`goHome`/`focusMoon`/`unfocusMoon`. Deep-link resolution + popstate handling lives in `applyRouteFromLocation()` (~line 12330), defined right before the final `animate()` call inside `bootHolotable()` (must be inside that closure — `activate`/`planetById`/`CASES` aren't exposed on window). **Bug hit and fixed:** first draft matched `parts[0]` directly against project slugs, forgetting the `/work/` prefix segment — always check `seg0==='work'` first, slug is `parts[1]`, moon slug is `parts[2]`.

**Required companion fix:** added `<base href="/">` in `<head>` (line 9). Without it, the site's relative asset paths (`./three.min.js`, `fetch('assets/manifest.json')`) resolve against the current nested path instead of site root, so any deep link two-segments-plus deep 404s on its own JS engine. This is a real, easy-to-forget gotcha for any future relative-path addition.

Also added `vercel.json` (didn't exist before) with an SPA fallback rewrite excluding `/api/`, `/assets/`, `/_vercel/` so direct hits/refreshes on `/work/slug` don't 404 on Vercel.

Verified via headless Playwright + a real local static server (mimicking the vercel rewrite) + real `three.min.js` fetched via npm pack — not just unit-testing the JS in isolation. Confirmed: slug auto-suggest from title, edit+persist+collision-handling, live URL update on open/close, deep link for project/moon/CV/HoloNet, unknown-slug graceful no-op, browser back/forward round-trip. See workflow-html-verification.md for the standing verify pattern this followed.
