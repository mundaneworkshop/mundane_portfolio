# Star Wars UI visual DNA

> Full Star Wars UI visual DNA — color system, motion archetypes, geometry, typography, and display component families — derived from analysis of 49 reference frame sequences (Jun 15 2026). Backs the visual-language-direction.md rules.

**Color semantic system (a state machine in the source material):** red = alarm/threat/unacquired; amber = selected/pending/warning (this is BRIC DS's home-base color); green = confirmed/acquired/safe; blue/cyan = neutral/navigation/reference; white = lock-on/maximum-intensity/critical.

**6 motion archetypes observed:** constant-velocity rotation (radar sweep, linear, no easing); progressive materialization (draw-in/particle-to-form, linear assembly); event-triggered burst (fast attack, slow decay); convergence/lock-on (ease-out, dramatic deceleration); live data stream (discrete cut updates, no interpolation); ultra-slow orbital drift (ambient/idle).

**8 display component archetypes:** targeting/lock-on scopes, system status/power allocation, radar/tactical, orbital/trajectory, technical schematic/3D analysis, tactical map/threat assessment, waveform/telemetry, database/identity terminal.

**What Star Wars UI never does (hard constraints that validate several BRIC DS rules):** no spring physics or bounce; no fade-in (elements draw in or simply appear); no smooth number transitions (counters cut, not tween); no drop shadows (only phosphor glow on literally-emitting elements); no rounded containers on screen content; no color present unless semantically required.

**What this validated in BRIC DS:** the amber-monochrome approach is historically consistent with the physical prop displays it's referencing; the bloom-quarantine rule is correct (only literally-glowing objects glow in the source material); the Aurebesh-reveal animation matches the live-updating ambient data register pattern seen in the sequences.
