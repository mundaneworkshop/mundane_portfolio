# First-visit asset loading: gate loader (Oct 29 2026, PR #106)

**Rule (owner's call):** a visitor never sees a placeholder sphere. "I would rather the entry gate show a loader before visitors are able to click through to the galaxy view than risk visitors seeing empty assets." Every model in `assets/manifest.json` must be downloaded AND built into the scene before the gate can be clicked.

## What went wrong before
PR #92 ("lazy seed") stopped boot from waiting on five heavy models and made `BRICStore.get(key)` wait for a lazy key's seed. The wait was put in the SECOND `BRICStore` definition (the canonical-looking one near the end of the file), which never installs: it bails out when the seed script's early copy exists, and that copy always runs first. The scene read the lazy moons before they were seeded, got `undefined`, and kept placeholder spheres until a refresh. Failed fetches were also swallowed with no retry. Lesson: any change to how the store reads must go in the early seed-script copy.

## How it works now
- **Seed script (early IIFE, grep `FIRST-VISIT ASSETS`)**: every manifest key gets a deferred (`window.__mwPending`); the live `BRICStore.get` waits on its key's deferred. A deferred resolves when the record is stored (or already cached), never on failure, so a failed key holds the gate instead of handing the scene `undefined`. `fetchRetry`: 4 attempts, 1/3/9 s backoff, retries bypass the HTTP cache, 90 s stall abort. Keys sharing a file share one download.
- **`window.MWAssets`**: state (`loading` / `failed` / `ready` / `released`), `percent()` (real bytes: manifest `bytes`, corrected by Content-Length; GLBs stream), `retry()`, `release()` ("Enter anyway"). Ready = all keys stored AND every boot-time restore built (`MWAssets.applyBegin(key)` from `restorePlanetOverrides` / `restoreMoonOverrides`, then `MWAssets.kick()`). A build that never reports back is released after 20 s with an error, so the gate can't hang on it. 30 s with no progress = `failed` (stalled), shown honestly.
- **Order**: on the gate route the models start downloading only once the monogram cube is up (`mwLoad` calls `MWAssets.start()`; 30 s backstop), so the cube isn't competing with ~7 MB of models. Cache checks don't wait: on a warm visit every key settles from IndexedDB straight away, so the gate is ready before it settles and the loader band never flashes. `<link rel=preload>` in the head starts three.js, the GLTF/Draco loaders and the monogram bundle with the HTML instead of after it.
- **Gate** (`gateBandsFrame`): while not ready, ONE marquee band on the H1 loop reads `LOADING ASSETS XX%` (same font, colour, lift and loop as the H1 band; tighter tracking and at least 2 repeats so the number is always on the front; redrawn in place, no rebuild). When ready it fades out (`gateFade`) and the two text bands fade in. `startDock` refuses to run until `MWAssets.canEnter()`; the reticle's ENTER frame is hidden while locked; `#gateHint` drops "click holocron to enter" until it can. Warm visits (everything cached) are ready before the gate settles, so the loader band never shows and the gate is unchanged.
- **`#mwLoad`** (DOM): on the gate it is screen-reader-only progress (`role=progressbar`, polite live region announcing every 25% and state changes, `aria-busy`) plus an Enter button that appears when focused (keyboard entry, `aria-disabled` with the reason while loading). If loading fails it shows visibly under the cube: "N assets didn't load", Retry, Enter anyway. Deep links and reduced-motion visits skip the gate, so there it is a full cover with `LOADING ASSETS XX%` and a progress bar that lifts by itself when ready.
- Debug: `window.__mwSeedLog` (per-key state, tries, ms), `MWAssets.startedAt / seededAt / readyAt`.

## Cache headers (checked)
`/` and `/assets/manifest.json` are `max-age=0, must-revalidate`; GLBs/JPGs are 7 days + SWR and every changed model gets a new versioned file name (`-v2`); vendor files are immutable. A deploy can't pair a stale page or manifest with renamed assets. Keep renaming files when their content changes.

## If you add a model
Add it to the manifest with its `bytes` (file size; only feeds the percentage, Content-Length corrects it). If the scene builds it at boot, wrap that build in `MWApply(key)` like the existing restores, ending it on every path.
